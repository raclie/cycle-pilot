# 安全な取得と根拠の回収

## 適用範囲
非公開repo、長い作業履歴、ツール応答を取得・表示するときに使う。保存・編集・送信の権限は付与しない。担当固有のより厳しい読取禁止、所有、停止条件を弱めない。

## 取得前に決める
目的、許可された取得元、必要なpath・版・範囲、返却され得る機微情報を確認する。既知の個別ファイルや固定blobを優先し、必要な行範囲を指定する。取得済みの固定資産を再利用できる場合、HEAD更新だけで全履歴を取り直さない。

読取禁止の箇所や機密が混在し得る履歴は、取得元で許可範囲に限定できる経路を確認する。全文を取得してから表示用に除外しても、取得自体の禁止を守ったことにはならない。toolの行数指定・画面切取りは、provider内部で取得前の限定が実施された証拠とは限らない。安全な経路が未確認なら、その取得を保留し、独立して許可された作業は続ける。

## GitHubと一覧応答
GitHub Contentsの一覧等は認証パラメータ付きdownload URLを含む場合がある。個別のfetch_file、またはpath・type・SHA等のGit tree情報で足りる場合はそちらを使う。必要のないdownload URLや生応答全体を表示・保存しない。認証値を別クライアントへ持ち出したり、接続の代替資格として再利用したりしない。

一覧の欠落、検索結果0、取得失敗を、担当や成果が存在しない証明にしない。停止中・目的未定義・保管専用repoを、読取できたことだけで稼働対象に変更しない。

## 根拠を記録する
通常はrepo、固定commitまたはblob、path、確認日時、確認範囲、判断と未確認事項を残せばよい。原文・応答の全面コピーを必須にしない。相手の採用記録は依頼ID・対象版・適用範囲を照合し、送り手の自己報告やその転載と区別する。別依頼から同じ課題が進んだ場合は関連観測として記録し、元依頼のACKに付け替えない。

## 誤取得・誤出力が起きた場合
値を再取得・再表示・再送せず、取得／表示／保存のどこまで分かるかを区別して記録する。有効性、閲覧者、provider保持、悪用、対策効果は根拠なしに断定しない。利用者へ事実と未確認範囲を報告し、資格の失効などは正規管理者の範囲で扱う。別ツールへの切替で読取禁止や拒否を迂回しない。

## 限界
この規則は、特定のMissionや実行主体に固有の操作手順・基準を含まない。

規則を保存しただけでは全hostでの強制適用や漏えい防止効果は未確認。取得前の判断、実際の使用、再発の有無は利用側の既存記録で確認する。新しい共有ログへ機微情報を集約しない。
